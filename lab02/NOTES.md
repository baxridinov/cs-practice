Рабочая папка, индекс и коммит
Рабочая папка (working directory) — это набор файлов на диске, которые я вижу и редактирую. Здесь происходят все изменения: правки текста, создание и удаление файлов.
Индекс (staging area) — промежуточная область между рабочей папкой и историей. Сюда попадают изменения после команды `git add`. Именно содержимое индекса фиксируется в следующем коммите.
Коммит (commit — снимок индекса, сохранённый в истории репозитория. У коммита есть уникальный хеш, автор, дата и сообщение. Коммиты образуют цепочку, по которой можно откатываться и сравнивать версии.
Git и GitHub
Git — распределённая система контроля версий. Работает локально на компьютере, не требует интернета. Хранит всю историю в папке `.git`. Может использоваться без GitHub.
GitHub — облачный хостинг для Git-репозиториев. Добавляет совместную работу: pull requests, issues, code review, CI/CD, Pages. Сам по себе не является системой контроля версий — это надстройка над Git
## Использованные команды

- `git status` — показывает текущее состояние: какие файлы изменены, какие в индексе, какие не отслеживаются.
- `git diff` — показывает разницу между рабочей папкой и индексом (что ещё не добавлено).
- `git diff --staged` — показывает разницу между индексом и последним коммитом (что уйдёт в следующий коммит).
- ## Ветки

**Ветка** — это подвижный указатель на коммит. Она позволяет вести параллельную работу, не затрагивая основную линию.

При **новом коммите** указатель текущей ветки автоматически сдвигается на новый коммит. Другие ветки остаются на своих местах.

**Слияние (merge)** объединяет изменения из одной ветки в другую. Если истории разошлись, создаётся коммит слияния (merge commit) с двумя родителями.
