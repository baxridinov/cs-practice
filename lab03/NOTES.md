# Воркшоп Git — журнал

## Сравнение версий и поиск изменений

### Чем отличаются git diff, git show и git log

- git diff — показывает разницу между двумя состояниями: рабочей папкой и индексом, индексом и последним коммитом, или между двумя любыми коммитами. Выводит только изменённые строки, без метаданных.
- git show <коммит> — показывает один конкретный коммит целиком: автора, дату, сообщение и полный дифф этого коммита относительно родителя.
- git log — показывает историю коммитов: хеши, авторов, даты, сообщения. Без диффов; с флагом --stat добавляет список изменённых файлов.

Итого: diff — сравнение, show — один коммит, log — список коммитов.

### Что нашли git log -S"def" и git blame

- git log -S"def" ищет коммиты, в которых добавлялась или удалялась строка с подстрокой def. В нашем случае — коммиты, где появлялись функции add, sub, mul.
- git blame lab03/calc.py построчно показывает, какой коммит и автор последним менял каждую строку файла.
## Восстановление файла

- git restore <файл> возвращает файл из индекса (а если в индексе ничего нет — из последнего коммита) в рабочую папку. То есть отменяет несохранённые правки.
- git restore --source=HEAD~2 <файл> берёт версию файла из указанного коммита (здесь — два коммита назад) и кладёт её в рабочую папку. Так можно посмотреть или вернуть старую версию, не трогая историю.

Оба варианта перезаписывают рабочую папку. Если бы у меня были несохранённые правки в файле — они бы потерялись безвозвратно, потому что git restore не кладёт их в индекс и не создаёт коммит. Отсюда правило: перед restore либо коммить, либо складывать в stash.
## Ошибочный коммит и его отмена

- git revert HEAD создаёт новый коммит, который отменяет изменения указанного коммита. История сохраняется: старый коммит с ошибкой остаётся, а поверх появляется коммит-отмена.
- git reset --hard HEAD~1 удаляет последний коммит и все незакоммиченные изменения рабочей папки. История переписывается: коммита с ошибкой как будто не было.

Почему в опубликованной истории безопаснее revert:
- Если коммит уже отправлен на GitHub и кто-то другой его скачал, reset --hard создаст расхождение: у вас история одна, у них — другая. Придётся делать force push, что ломает работу коллег.
- revert не переписывает историю — просто добавляет отменяющий коммит. Пуш проходит обычным git push, ничего не ломается.
- Правило: в локальной истории (ещё не пушил) можно reset, в опубликованной — только revert.
